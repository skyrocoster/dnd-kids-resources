# Frontend

React and Vite client; frontend commands are defined in `package.json`.

- `src/` — application, tests, Storybook stories, and theme token tools
- `src/tools/` — theme token generators and the known-test-failure checker
- `.storybook/` — Storybook configuration
- `tests/e2e/` — browser-level Playwright tests

Run the palette tests from `frontend/` with:

```powershell
npm run test -- src/__tests__/derive-kid-palette.test.mjs
```

Theme tokens are generated by the Node tools in `src/tools/`.

## Browser tests

The E2E setup uses both npm package directories. From the repository root,
install the Playwright test and accessibility packages needed by the root-level
test config; then install the frontend packages (which provide the `test:e2e`
command):

```powershell
# Repository root
npm ci

# frontend/
Set-Location frontend
npm ci
npx playwright install chromium
npm run test:e2e
```

The Playwright configuration starts or reuses Vite at `http://localhost:5173`.
For app specs it also reuses a backend responding at `http://localhost:8000`, or
starts a short-lived host Uvicorn backend there when none is available. Vite
proxies `/api` requests to that backend. The health spec makes a live request to
`/api/health` through Vite. Weapon CRUD specs intercept API routes with
controlled responses, so those tests do not prove database writes against the
backend. The Storybook spec uses Storybook at port `6006` (different from the
Compose address in the development-services guide). See
[`docs/DEVELOPMENT_SERVICES.md`](../docs/DEVELOPMENT_SERVICES.md) before using
the shared development services; do not start competing servers manually.

## Storybook

Run Storybook locally from this folder with:

```powershell
npm run storybook
```

It uses port `6006`. To check catalog conventions, build the static version, or
run the stories in Chromium:

```powershell
npm run test -- src/storybookConventions.test.ts
npm run build-storybook
npm run test:storybook
```

The catalog is grouped under `Production`, `In Development`, and `Reference`,
with a matching `status-*` tag. The convention test checks that every
application TSX module is reachable from a story, story names are unique within
each section, and responsive stories use the shared viewport presets. The
preview loads the application dark theme and returns deterministic local data
for API-backed stories, so Storybook does not require Docker or a campaign
database.
