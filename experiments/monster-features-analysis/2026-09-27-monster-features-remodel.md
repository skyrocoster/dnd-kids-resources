# Monster features remodel — output objectives

1. Simpler, useful monster feature model, where some source detail may be omitted where it does not serve use.
2. Explicit feature categories covering traits, actions, and other feature kinds.
3. Defined rule for when a monster feature references a shared entity versus carrying its own definition.
4. Defined representation for different use modes of one shared entity.
5. Defined set of monster-specific values retained alongside a shared reference.
6. Defined merge rule under which similarly named actions stay distinct when their differences are material.
7. Defined equivalence rule stating which fields make two mechanics the same reusable action.
8. Separate handling of display naming and underlying mechanics, so distinct mechanics are not silently conflated and display differences are preserved.
9. Material modes, damage components, extra effects, descriptions, and source inconsistencies remain explicitly represented rather than silently dropped or merged.
10. Defined place for non-weapon actions that does not drop them for lacking a shared-entity link.
